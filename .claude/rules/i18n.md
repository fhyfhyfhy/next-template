# i18n

User-visible text is translated with next-intl. `lib/i18n/routing.ts` lists the locales; `zh` is both the default locale and the [source locale](../../GLOSSARY.md) that new text is written in. URLs follow [ADR 0002](../../docs/adr/0002-locale-routing-as-needed-prefix.md): the default locale has no prefix, others live under `/{locale}`.

## What gets translated

- Everything a user sees or hears: JSX text, `aria-label` and other accessible names, `title`, `placeholder`, `alt`, toasts, validation and error messages, and `metadata`.
- Not translated: user and backend content such as task names and comments, `ApiError.message` and other developer-facing logs and thrown errors, and code comments.
- Files in the UI demo's `features/demo-ui/components/*-examples/` directories keep literal text: examples and playgrounds stay copyable without message keys, control labels are prop names, and the index generator reads component metadata as literals.

ESLint's `i18next/no-literal-string` reports literal text in JSX and in the attributes listed in `eslint.config.mjs`. Text outside JSX, such as toasts, `metadata`, and labels in constants, is not checked: route it through `t()` all the same.

## Writing text

Claude translates every locale itself, in the same change as the code:

1. Render the text with `t()` (see "Reading messages").
2. Write the source-locale text in `messages/zh/{namespace}.json`, then the translation in the same file under every other `messages/{locale}/`. Edit the JSON files directly. Leave no empty value, placeholder, or TODO for a later translator.
3. Follow `messages/terms.json`: a term under `keep` stays as written in every locale; a term under `translations` uses the listed translation. Add a term when the same word must read the same way across the product.
4. Changing source-locale text means translating it again in every locale. Removing code removes its keys from every locale; nothing reports unused keys.
5. Run `pnpm test messages/messages.test.ts`. It fails when a locale's files or keys differ from the source locale, a message is empty or not valid ICU, its arguments or tags differ from the source, or a translation misses a term.

Use ICU syntax for values, plurals, and rich text, such as `{count, plural, other {# tasks}}`, and pass values to `t()`. Translate whole sentences; don't concatenate translated fragments.

## Namespaces and keys

- One namespace per owner, one file per namespace: a feature's directory name (`demo-task`), `app` for text in `app/`, and `ui` for `components/` and `components/ui/`. There is no shared `common` namespace. Text in `app/` nests by route, such as `demos.tasks.title`.
- A file holds its namespace's keys without a namespace wrapper; `lib/i18n/messages.ts` adds it on load. A new namespace needs its file in every locale and an entry in both `Messages` and `NAMESPACES` there.
- Code uses only its own owner's namespace. To show another feature's text, render that feature's component through its public entry.
- Keys are camelCase, nested by component or area and then by meaning: `taskList.emptyTitle`, `errors.nameTaken`. Name a key after what the text means, not its wording; the same words with different meanings get separate keys.

## Reading messages

| Where | How |
| --- | --- |
| Server Component | `useTranslations(namespace)`, or `await getTranslations(namespace)` in an async one |
| `generateMetadata` | `await getTranslations(namespace)` |
| Client Component | `useTranslations(namespace)`, with the namespace sent by `ClientMessages` (below) |
| Server Action, Route Handler | `await getTranslations({ locale, namespace })`. They can't read root params, so the caller passes `locale` from `useLocale()`; a mutation passes it as an options factory argument |
| Code outside React, such as a `QueryClient` callback | Render a component that calls the hook, as `RequestErrorMessage` in `app/providers.tsx` does |

Client Components receive only the namespaces their route sends. The root layout sends `app` and `ui` (`BASE_CLIENT_NAMESPACES` in `lib/i18n/messages.ts`). A route layout wraps its subtree in `<ClientMessages namespaces={[…]}>` from `lib/i18n/client-messages.tsx`, listing every other namespace its Client Components use; a nested `ClientMessages` replaces the outer one's messages, so list them all. When a Client Component starts using a namespace, or a route starts rendering another feature's Client Components, update the nearest `ClientMessages`. A missing namespace renders `namespace.key` and logs a `MISSING_MESSAGE` error, which fails any e2e test that loads the page (`e2e/test.ts`).

## Validation and API errors

- A zod schema whose messages users see is a factory that takes `t`, such as `createTaskNameSchema(t)`. Forms build it with `useTranslations` inside `useMemo`; a Server Action builds it from `getTranslations({ locale, namespace })`. The messages reach the UI already translated.
- `ApiError.message` is written for developers. Show copy from the owning feature's namespace, chosen by `error.code` or `error.status`, and pass `error.params` to `t()` ([data-fetching.md](data-fetching.md#errors-in-react-queryowned-data)).

## Dates and numbers

Format with next-intl's `useFormatter()` or `getFormatter()`, never an `Intl` formatter with a hard-coded locale. `lib/i18n/request.ts` sets the locale and a fixed time zone, so server rendering and hydration produce the same text.

## Navigation

Import `Link`, `redirect`, `permanentRedirect`, `useRouter`, `usePathname`, and `getPathname` from `@/lib/i18n/navigation`. ESLint rejects `next/link` and the `next/navigation` exports of the same names, which drop the prefix of non-default locales. Hrefs omit the locale (`/demos/tasks`), and `usePathname` returns the path without it.

`components/locale-switcher` switches the locale of the current page with full-page links; its comment explains why it doesn't use `Link`. It shows each language's name in that language, the same in every locale, so those names stay out of `messages/`.

## Adding a locale

Add it to `routing.locales` in `lib/i18n/routing.ts`, create `messages/{locale}/` with every namespace file translated, add its translation to each entry in `messages/terms.json`, and run the messages test.
